# Как участвовать в разработке

Проект команды **2nd_try** — веб-сервис проектирования устойчивой спутниковой группировки
(кейс А КосмоХакатона-2026). Ниже то, что нужно знать, прежде чем присылать изменения.

## Как предложить изменение

- **Обсуждение или задача (issue)** — если меняется модель расчёта, контракт `/ws` или формат
  выгрузки. Такие правки затрагивают сходимость с эталоном, их стоит обсудить до кода.
- **Запрос на слияние** — для всего остального: исправления, интерфейс, документация.
  Ветвиться от ветки по умолчанию, одна ветка — одна законченная тема.

## Требования к коду

- **Расчётное ядро отделено от веб-слоя.** `backend/core/` не содержит ни одного импорта из
  веб-слоя; веб-слой принимает сообщения и зовёт ядро. Нарушение этой границы — причина отклонить
  запрос.
- **Геометрия не переписывается.** `backend/core/geometry.py` — побайтовая копия эталонного
  модуля из условий задачи. Свои формулы, своя нормализация углов, шаг в минутах вместо секунд —
  всё это ломает сходимость с эталоном.
- **Один транспорт.** Весь обмен идёт по `/ws` конвертом `{id, type, payload}`; из REST есть
  только `/health`. Новая REST-ручка для того, что должно идти по `/ws`, не принимается.
- **Никакого хардкода данных сценария.** Идентификаторы пунктов и аппаратов, число плоскостей,
  число отсчётов сетки читаются из загруженного файла. Жюри загружает другой сценарий того же
  формата с другими ID.
- **Язык.** Интерфейс, документация и комментарии — по-русски; идентификаторы в коде — по-английски.
  В каждом модуле докстринг на одну-две строки: назначение и инварианты.
- **Документация правится тем же коммитом, что и код.** Меняется контракт `/ws` — правится
  `docs/PROTOCOL.md`; меняется формат выгрузки или команда запуска — правится `README.md`.
  Разошедшийся с кодом документ хуже отсутствующего.
- Мёртвый код, закомментированные блоки, `TODO` и заглушки в запрос на слияние не попадают.
- **Линтер и автоформаттер в проекте не настроены** — намеренно: за стиль отвечает ревью, за
  корректность тесты и сверка с эталоном. Не добавляйте прогон линтера в CI отдельным запросом,
  не обсудив: массовое переформатирование перемешивает содержательные правки с косметикой.

## Чек-лист перед запросом на слияние

Прогоняется локально, результат приводится в описании:

```bash
pip install -r backend/requirements-dev.txt

python3 -m pytest backend/tests     # 73 теста
python3 tools/golden.py             # сверка расчёта с эталоном по четырём сценариям
docker compose up --build           # сервис поднимается одной командой на :8000
```

Если менялся формат выгрузки — дополнительно `python3 tools/golden.py --result <файл.json>`:
проверяются схема, полнота, допустимость каждого маршрута и сходимость с эталоном.

Утверждение о доступности или перерывах без числа и команды, которой оно воспроизводится,
в описании не принимается: «стало лучше» — это не результат.

## Формат коммитов

Заголовок — до 72 символов, по-русски, без точки в конце. Дальше пустая строка и тело, которое
объясняет **почему**, а не пересказывает diff. Пример:

```
Список платформ публикации стал параметром

Сборка под linux/arm64 на amd64-хосте требует зарегистрированного эмулятора
и нескольких ГБ свободного диска. Без них скрипт падал уже после создания
билдера; теперь платформы задаются переменной CONSTELLATION_PLATFORMS.
```

## Ревью

Смотрит кто-то из команды 2nd_try. Отвечаем по возможности в течение суток — команда небольшая,
жёсткого SLA нет. Ревью проверяет три вещи: сходимость с эталоном, границу ядро/веб-слой и
соответствие документации коду.
